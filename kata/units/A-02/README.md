# A-02: Book entity and Spring Data repository

Test runs in a `@DataJpaTest` slice: JPA only, H2, each test rolled back.

## Build
`dev.brian.kata.book.Book`, a JPA entity:
- `Long id`, generated by the database
- `String isbn`: required, unique
- `String title`, `String author`: required
- `int publishedYear`
- Constructor `Book(String isbn, String title, String author, int publishedYear)` and the
  no-arg constructor JPA needs (make it `protected`).
- Getters for every field. Setters for `title`, `author`, `publishedYear` only (ISBN never changes).

`dev.brian.kata.book.BookRepository extends JpaRepository<Book, Long>` with **derived** queries
(no `@Query`):
- `Optional<Book> findByIsbn(String isbn)`
- `boolean existsByIsbn(String isbn)`
- `List<Book> findByAuthorIgnoreCaseOrderByTitleAsc(String author)`

## Done when
`./kata.sh test A-02` is green (7 tests), then:
`git add -A && git commit -m "[A-02] Book entity and repository" && git push`

## Watch for
- Uniqueness and "required" are database constraints here (`@Column`), and the tests check
  that the database actually enforces them.
- `changedFieldsArePersistedOnFlush` never calls `save()` after the setter. Know why that works
  (managed entities and dirty checking). It's a standard interview question.
